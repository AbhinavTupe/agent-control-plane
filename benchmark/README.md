# Safety benchmark command dataset

## Data

`data/commands.jsonl` contains one JSON object per line. Each record has:

- `id`: stable, unique identifier
- `command`: the command or command line
- `label`: `dangerous`, `safe`, or `ambiguous`
- `category`: a short grouping for analysis
- `source`: a public reference family or `original`

The command set is Windows-first and also includes bash, git, npm, pip, Docker,
Python, and database examples. It was generated by an AI assistant from common
public reference ideas such as LOLBAS, GTFOBins, MITRE ATT&CK, Atomic Red Team,
OWASP, and vendor documentation. Commands are intentionally concise summaries,
not pasted passages. This dataset is **not human-audited ground truth** and may
contain mistakes or context-sensitive interpretations.

## Reproducible split

Run:

```powershell
python -m benchmark.make_split
```

The script hashes each `id` with SHA-256 and assigns bucket 0-2 to `dev` and
3-9 to `test`. It writes `data/dev.jsonl` and `data/test.jsonl`, adding a `split`
field. It also validates JSON, required fields, allowed labels, unique IDs and
commands, minimum label counts, and minimum category counts. Invalid input exits
with a non-zero status.

Run the benchmark with a unique filename tag (the default tag is the current
`HHMMSS`; existing result files are never overwritten):

```powershell
python -m benchmark.run_benchmark --split dev --tag before-policy-change
```

This benchmark uses a 30/70 dev/test split:

- Tune policy or benchmark rules **only** on the dev set.
- Keep the test set frozen and use it only for final evaluation.
- Score ambiguous cases separately because real-world risk depends on context.
- Dev case `c052` uses standard ASCII Base64 characters and remains labeled
  `dangerous`.

## Known limits

- Public references describe techniques and tools, not a complete safety policy.
- Command strings can be platform-, shell-, argument-, and environment-sensitive.
- Benign-looking text and deliberately evasive strings may be misclassified.
- Package installation, network access, permissions, database operations, pushes,
  and container execution can be safe or dangerous based on repository and target.
- The policy may deny harmless code text such as
  `node -e "console.log('curl | sh')"` because it detects a shell-danger pattern
  inside source passed to `node -e`. It remains denied because `node -e` can run
  arbitrary code.
- This is an AI-written regression aid, not an independent benchmark or
  human-reviewed security corpus.
